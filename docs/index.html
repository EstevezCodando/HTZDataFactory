HTZDataFactory

Sistema Docker + DDD para geração automática de arquivos binários nativos ATDI (.geo, .sol, .img, .pal) para HTZ Warfare e ICS Telecom a partir de dados abertos — FABDEM, MapBiomas e imagens de satélite.

🛰 Fontes de Dados

DEM: FABDEM v1.2 (University of Bristol, CC-BY-4.0)
Clutter: MapBiomas Collection 10 2023 (CC-BY-4.0)
Imagem: Sentinel-2 L2A (ESA), Google Satellite, Bing Satellite, OSM

📦 Saídas ATDI

.geo — Elevação int16 LE, 30 m/px
.sol — Clutter uint8, 30 m/px
.img — Imagem uint8, 15 m/px
.pal — Paleta 240 entradas × 30 bytes

⚡ Características

Jobs assíncronos via Celery + Redis
Preview interativo de tiles no mapa
Download FABDEM por demanda
Efeito cebola urbano automático

🔒 Segurança

CORS restrito a origens locais
Rate limiting por endpoint
Validação de magic bytes em uploads
Path traversal bloqueado

Adaptadores de Infraestrutura

atdi_writer.py — Writer Binário ATDI

Gera o header de 1010 bytes e os dados de pixel para cada tipo de arquivo ATDI. Único ponto de geração de binário no sistema.

FunçãoRetornoResponsabilidade
write_geo(path, data, xmin, ymin, px, lon, south)—Elevação int16 little-endian, 2 bytes/pixel
write_sol(path, data, xmin, ymin, px, lon, south)—Clutter uint8, 1 byte/pixel (códigos 0-11)
write_img(path, data, xmin, ymin, px, lon, south)—Imagem grayscale uint8, 1 byte/pixel
write_pal(path, palette_flat)—240 entradas RGB × 30 bytes = 7200 bytes
write_pal_grayscale(path)—Rampa cinza R=G=B=i para uso com .img
_build_header(...)bytes[1010]Header ATDI com UTM, dimensões, false northing
⚠ False Northing EPSG:327xx adiciona 10.000.000 m ao Y (hemisfério sul). O ATDI espera Y negativo. O writer subtrai automaticamente quando south=True: yatdi = yepsg − 10.000.000

tile_downloader.py — Download MBTiles

FonteKindZoomURL / Protocolo
Google SatelliteXYZ12-18mt1.google.com/vt/lyrs=s&x={x}&y={y}&z={z}
Bing SatelliteQuadkey12-18ecn.t{s}.tiles.virtualearth.net/tiles/a{q}.jpeg
OpenStreetMapXYZ12-17tile.openstreetmap.org/{z}/{x}/{y}.png

Conversão Quadkey (Bing): para cada bit do zoom do maior para o menor, testa se X tem o bit setado (+1) e se Y tem o bit setado (+2).

Y TMS: SQLite MBTiles usa convenção TMS onde y_tms = 2^z − 1 − y_xyz

Formato Binário ATDI — Header 1010 bytes

Header idêntico para todos os tipos (.geo, .sol, .img). Descoberto por engenharia reversa do arquivo de referência 06S035W.sol (área de Natal, RN).

Formato .pal (7200 bytes)

O arquivo .pal é uma LUT (look-up table) exclusiva do arquivo .img. O .sol (clutter) não usa .pal — o HTZ usa suas próprias configurações de cores para clutter.

✔ Formato confirmado por análise hex Referência: 06S035W.pal (área de Natal, 7200 bytes)
708 de 720 campos usam o formato simples. 12 exceções nas entradas 236–239 são valores decimais raros irrelevantes para nossa paleta.

Estrutura

240 entradas × 30 bytes = 7200 bytes

Por entrada (30 bytes):
  Canal R:  10 bytes
  Canal G:  10 bytes
  Canal B:  10 bytes

Por campo (10 bytes) — formato Natal (confirmado):
  str(valor).encode('ascii') + b'\x00' * (10 - len(str(valor)))

Exemplos:
  valor=0   → b'0\x00\x00\x00\x00\x00\x00\x00\x00\x00'
  valor=31  → b'31\x00\x00\x00\x00\x00\x00\x00\x00'
  valor=240 → b'240\x00\x00\x00\x00\x00\x00\x00'

Engenharia Reversa do Formato ATDI

Processo de 10 passos para descobrir e validar o formato binário a partir do arquivo de referência 06S035W.sol (área de Natal, RN).

Resumo do Processo

PassoFerramentaDescoberta
1Notepad++Arquivo não é puramente binário — há bloco ASCII antes dos dados
2HxD (hex editor)Primeiros 160 bytes = zeros. Conteúdo ASCII começa em 0x0A0. Dados em 0x3F2 (offset 1010)
3ASCII decode manual4 cantos UTM em ASCII com separadores \x00\x00 entre X e Y de cada canto
4HxD — offsets fixosByte 300 = 'M' (metros). Bytes 320/330 = largura/altura. Bytes 340/371 = código UTM
5Cálculo manualzona = int((lon+180)/6)+1. Confirmado para lon=-43° → zona 23 → "UTN23"
6HTZ softwareY no HTZ = negativo no HS. Diferença = 10.000.000 m (false northing EPSG:327xx)
7Cálculo tamanho.sol: 1 byte/pixel (uint8). .geo: 2 bytes/pixel (int16 LE). .img: 1 byte/pixel (uint8)
8HxD — .pal7200 bytes = 240×30. Formato campo: ASCII + null-padding até 10 bytes
9Writer PythonComparação byte-a-byte com arquivo original → 100% idêntico
10HTZ importEfeito cebola visível. Paleta correta. Coordenadas precisas sobre a área
⚠ Armadilha Principal — False Northing EPSG:327xx retorna Y positivo: ex. 9.565.430 m
ATDI espera Y negativo: ex. −434.570 m
Correção: y_atdi = y_epsg − 10.000.000
Sem isso o arquivo abre no HTZ 10.000 km ao norte da posição correta.
